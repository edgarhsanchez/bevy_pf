# MAUI → bevy_pf: the migrant's gap matrix

Written 2026-08-06. Purpose: make bevy_pf's XAML good enough that a
developer arriving from .NET MAUI finds what they expect — or a one-line
rename away from it. Comparison anchor:
[MAUI multi-project migration guide](https://learn.microsoft.com/en-us/dotnet/maui/migration/multi-project-to-multi-project?view=net-maui-10.0)
plus the MAUI XAML fundamentals, controls, binding, and styling references
on Microsoft Learn.

**Method.** Twelve-agent verified sweep: four researchers inventoried the
MAUI XAML surface from Microsoft Learn, two inventoried bevy_pf's actual
implemented surface (with file:line anchors) and the existing
Noesis-derived roadmap, one synthesized the matrix, four adversarially
re-checked every row against the code, and a completeness critic hunted
for concepts with no row. 131 rows; 19 were corrected in verification —
in both directions (claimed gaps that already work, claimed support that
was thinner than it looked), which is why the verification pass exists.

## Headline

| status | count | meaning |
|---|---|---|
| ✅ supported | 64 | works today, usually as a WPF-dialect rename |
| 🟡 partial | 29 | core works, named edges missing |
| 🗓 planned | 2 | already on the Noesis-derived roadmap |
| ❌ gap | 22 | not implemented |
| — not applicable | 14 | platform plumbing that has no Rust/game-engine analog |

Roughly half of MAUI's XAML surface works today under its WPF name, and
the entire first-hour path — layouts, core controls, StaticResource,
implicit styles, Binding basics — is either supported or one rename away.
The three P1 items are all **binding ergonomics**, not missing controls.

## P1 — what a migrant hits in the first hour

**All three addressed 2026-08-06** (commits on the binding layer): 
`DataContext="{Binding path}"` works as an attribute via lazily-resolved
scope markers; bindings on any store-managed property (Margin, Padding,
BorderThickness, CornerRadius, Opacity, ...) route through the precedence
store's Local tier; and per-property change notification landed as
`Bindable::update_named` + a `#[derive(Bindable)]` that generates
equality-checked notifying setters. Original findings kept below for the
record:

- **BindingContext** (🟡 partial): Inherited DataContext works (including across popup logical-parent links), but only settable from Rust — no XAML DataContext= attribute, which migrants try in the first hour (DataContextChanged is accepted-and-ignored).
  - evidence: binding.rs:210-212 (DataContext component), :767-777 (find_context inheritance walk incl. PfLogicalParent); instantiate.rs:2789 (DataContextChanged ignored); grep confirms no DataContext= attribute arm in instantiate.rs
- **Bindable target property coverage (any BindableProperty)** (🟡 partial): Bindings only land on a 15-property allowlist (Text, IsChecked, Value, Visibility, brushes, sizes...); anything else warns 'not supported yet' — migrants hit this immediately on less common properties.
  - evidence: binding.rs:321-352 (BindingTarget enum, exactly 15 variants); instantiate.rs:7357-7405 (property match; catch-all warn at 7400-7405)
- **INotifyPropertyChanged view models** (🟡 partial): The MVVM pattern exists but is coarse-grained (whole-object version bump, no per-property notification, no derive macro); T2.2 plans #[bindable] and property-name granularity.
  - evidence: binding.rs:35-64 (BindableInner version: AtomicU64, bump on update); docs/roadmap-from-noesis-analysis.md T2.2 (a) changed-name SmallVec, (b) #[bindable] derive

## P2 — the first-week list (gaps and partials only)

- **FlexLayout** (❌ gap): WPF dialect has no flexbox; WrapPanel covers wrap-only cases, grow/shrink/basis and alignment semantics must be rebuilt with Grid.
- **TranslationX/Y, Rotation, Scale (VisualElement transforms)** (🟡 partial): RenderTransform with a transform element or resource IS applied to elements today (inserts UiTransform), and Storyboards animate ScaleX/ScaleY/Rotation/TranslateX/TranslateY. Still missing: matrix-string syntax, RenderTransformOrigin (silently ignored), LayoutTransform, and Skew/Matrix transforms (parse to identity) — those are roadmap T1.5/T2.5.
- **CollectionView** (🟡 partial): ItemsSource + DataTemplate + ItemContainerStyle work, but CollectionView's layout specs (grid/span), grouping, selection modes and virtualization semantics have no direct mapping — SelectionMode is accepted-and-ignored, and VirtualizingStackPanel aliases to plain StackPanel.
- **ListView (cell-based: TextCell/ImageCell/ViewCell...)** (🟡 partial): No cell types exist; every cell must be rewritten as a DataTemplate (which is the WPF idiom anyway). GridView-mode ListView routes to DataGrid-style column rows.
- **GestureRecognizers (Tap/Pan/Pinch/Swipe/Pointer)** (🟡 partial): Tap and pointer enter/leave/down/up/move plus drag are wired; pinch/pan/swipe gestures are not.
- **Shell (FlyoutItem/TabBar/Tab visual hierarchy)** (❌ gap): No Shell equivalent; the app skeleton must be rebuilt from NavigationView/TabControl/Frame, all of which exist individually.
- **Page lifecycle (OnAppearing/OnDisappearing)** (🟡 partial): Loaded fires as an EventTrigger routed event (and as a behaviors EventTrigger EventName); Unloaded and code-behind Loaded= handler attributes are accepted-and-ignored, so no despawn/disappear hook exists.
- **ICommand / Command / CommandParameter** (🟡 partial): Command/CommandParameter bind and fire from Button family, MenuItem, Hyperlink and InvokeCommandAction (plus a PfCommandInvoked message for central handling), but CanExecute-driven auto-disable has no analog (grep: no can_execute anywhere); PfCommand with execute + can_execute + changed is planned (T2.2c).
- **DynamicResource** (🟡 partial): Live re-resolution works on direct properties and non-attached style setters — but only for the 13 store-managed PropertyTargets; other properties resolve once, eagerly, without live refresh. Attached-property setters are explicitly unsupported yet.
- **Style inheritance (BasedOn)** (🟡 partial): StaticResource-only and the base must be lexically earlier (missing base warns 'must be defined before use'). BasedOn={x:Null} already falls through as 'no base' without error, and qualified setter names (Control./FrameworkElement./UIElement./TextElement.) are already stripped; the remaining roadmap-T1.7 residue is only polish on those paths.
- **VisualStateManager (CommonStates, control states, Setter.TargetName)** (🟡 partial): VSM works inside ControlTemplates with auto-driven CommonStates/CheckStates/FocusStates and transitions, but MAUI attaches setter-based state groups to any element — that per-element, setter-based form is not covered.
- **ControlTemplate (ContentPage/ContentView templating)** (🟡 partial): Parsed fully (TargetType, triggers, VSM) but expansion is limited to nine control kinds; templating a page/UserControl root — MAUI's main use — warns 'not supported yet'.
- **TemplateBinding** (🟡 partial): Live forwarding works but only for the 13 store-managed properties; other properties skip with a warning instead of MAUI's silent failure. Valid as a trigger `Setter.Value` too, but there it resolves at activation rather than staying live.
- **Fonts (MauiFont registration, FontFamily, FontSize)** (🟡 partial): FontSize is store-managed and bindable and a fonts module exists (embedded Fira Sans, cross-platform family aliasing, fallback-list splitting); asset-URI FontFamily resolution ('#' family split) is roadmap T2.1.
- **x:Static** (🟡 partial): Strips the trailing identifier and feeds enum converters — which covers the enum-member form ({x:Static Visibility.Collapsed}) that roadmap T1.3 targets and themes actually use; no real static-member lookup (user constants), and the sys: primitives half of T1.3 is still unimplemented.
- **x:Class + code-behind partial class** (🟡 partial): No generated partial class; events wire through a Rust registry (named handlers dispatched via picking observers, silent when unregistered) and the two-callback XamlComponent/connect_event! contract is planned roadmap work. x:Class itself is nowhere handled in src (silently carried).
- **AppThemeBinding** (🟡 partial): Implemented with MAUI's exact pick rules (Unspecified resolves as Light; a missing arm falls back to Default only; an arm written `{x:Null}` counts as supplied and stops the fallback; no match and no Default writes null rather than reverting). Live on the store-managed properties via the shared refresh pass, one-shot elsewhere and on attached properties; attribute and Style/trigger Setter placements only, not the property-element form.
- **clr-namespace/using: xmlns for custom types** (🟡 partial): Custom controls register by local type name in Rust rather than by CLR namespace (`<local:Gauge>` matches a registration for "Gauge"); unknown-and-unregistered elements are NOT rejected — they warn once and degrade to a plain container. Foreign-namespace graceful skip with a single warning class is roadmap Tier-1 item 6.

## Known not-yet-analyzed (completeness critic)

Concepts the sweep did not row-ize; each needs its own pass before the
matrix is called complete:


- **Localization (resx + CultureInfo)** — explicitly on the checklist; no row covers `.resx` string resources, `IStringLocalizer`, or culture-aware formatting a migrant's `{x:Static resx:AppResources.Key}` pattern depends on.
- **FlowDirection / right-to-left layout** — `VisualElement.FlowDirection` (LTR/RTL/MatchParent) has no row; mandatory for any localized app targeting RTL languages.
- **ImageSource kinds** — the matrix rows only `Image (Aspect/Stretch)` and `FontImageSource`; `FileImageSource`, `UriImageSource` (with its caching options), `StreamImageSource`, and embedded-resource images have no row.
- **Single-project resource build actions** — `MauiImage`, `MauiIcon`, `MauiSplashScreen`, `MauiFont`, `MauiAsset` / raw assets (app icon and splash screen pipeline); only font *registration* is rowed.
- **Drag and drop** — `DragGestureRecognizer`/`DropGestureRecognizer`; the gestures row enumerates only Tap/Pan/Pinch/Swipe/Pointer.
- **Shadow** — `VisualElement.Shadow` (brush, offset, radius, opacity) has no row; distinct from Border/Frame decoration.
- **Clip** — `VisualElement.Clip` with a `Geometry` (clipping any view to ellipse/rect/path); no row despite Shapes/geometry being rowed.
- **FormattedString / Span** — rich multi-styled text inside `Label` (spans with gestures); the Label row alone doesn't cover it.
- **Margin / Padding (Thickness)** — fundamental box-model properties every migrated layout uses; the sizing row covers WidthRequest/IsVisible/Opacity but not these.
- **Context menus / MenuFlyout** — `FlyoutBase.ContextFlyout`, `MenuFlyout`/`MenuFlyoutItem` (right-click/long-press menus); only ToolbarItem/MenuBarItem are rowed.
- **Shell SearchHandler** — Shell's integrated search box (named in the research itself); the Shell rows cover hierarchy and navigation but not it.
- **CSS stylesheets** — `Microsoft.Maui.Controls.StyleSheets` (styling via CSS); appears in the research's namespace-mapping table but has no matrix row.
- **DisplayPromptAsync** — text-input prompt dialog; the modal row lists DisplayAlert/DisplayActionSheet only.
- **x:ClassModifier / x:FieldModifier** — access-level directives for the generated class and `x:Name` fields; present in the research's x: inventory, absent from the matrix.
